# 项目说明

[返回 README](../README.md) · [部署、优化与技术栈](deployment.md) · [Agent Skills 设计与集成](skills.md)

阅读论文时，真正打断思路的往往是一个陌生的方法名、一处引用，或者一句依赖背景知识的论述。读者需要离开 PDF，整理关键词、搜索文献、寻找全文，再回到原文继续阅读。随着问题不断深入，浏览器标签和下载文件越来越多，却很难记住“为什么打开这篇论文”，也难以回到最初产生疑问的位置。Paper Tree 围绕这一过程构建桌面阅读工作区，将问题、原文位置和后续论文保存在同一条探索路径中。

用户从一篇根论文开始，在保留原版面的 PDF 上框选想了解的内容。应用截取选框内的实际图像，交给视觉模型识别，用户可以核对并修正文字；随后模型结合论文主题与缓存的参考文献，保留学术术语和方法名称，将较长的原文整理成适合检索的查询。结果以候选列表呈现，提供真实来源、关联原因和相关性评分。用户选择论文并获取 PDF 后，新论文成为阅读关系图中的子节点，还可以继续向下探索。返回来源时，应用恢复页码和选框，让阅读从当时的问题继续。关系图表达的是读者的探索路径，而正式引用信息作为检索依据单独保留。

项目把 NVIDIA 技术贯穿研究执行与本地推理两部分。研究流程接入 NVIDIA 官方 `aiq-research` Agent Skill，通过其 Python helper 调用本机 NVIDIA AI-Q Blueprint 后台。AI-Q 基于 NVIDIA NeMo Agent Toolkit（NAT）配置研究 Agent，并使用 Paper Tree 注册的论文搜索工具访问 OpenAlex、Crossref 与 arXiv。研究返回带来源链接的报告，应用进一步解析其中的论文线索、核对学术元数据，将研究依据保存到当前探索记录。用户可以在界面查看 NVIDIA Skill 的研究报告，从而理解候选论文与当前问题之间的联系。

模型推理采用 NVIDIA DGX Spark 与 TensorRT-LLM 的部署方案：在 Spark 上通过 NVIDIA 官方容器运行开放模型权重，向桌面客户端和 AI-Q 提供 OpenAI 兼容接口。项目以 Qwen3.8-27B 为主力部署配置，并提供 Qwen3.5-9B 切换入口；模型与 Agent 通过接口分离，切换推理服务时可以沿用阅读、研究和建树逻辑。桌面端负责 PDF 交互、文件获取与数据保存，Spark 负责模型计算，本机 AI-Q 负责研究工具的执行与组织。这种分工让个人工作站上的算力能够直接服务于日常论文阅读。框选识别还要求接口提供支持图片输入的视觉模型，具体配置与验证范围见部署文档。

实现上，Electron 管理应用生命周期、模型配置、下载窗口与本地文件，React 和 PDF.js 提供连续阅读与区域选择，SQLite 缓存论文主题、参考文献和研究记录。查询阶段并行运行 Skill 研究与学术索引查询，利用已有参考文献定位具体论文，同时以概念关键词查找相关工作；汇总后排除当前论文、合并重复项，再让模型对候选逐篇评分并排序。结果数量由检索来源和去重结果决定，不为凑数补入无关论文，也不只留下单一答案。用户始终负责选择真正要阅读的论文。

优化围绕单用户的交互体验展开。应用复用论文索引，避免每次查询重复解析全文；检索提示保留必要上下文，研究报告保持简短，减少无关生成。推理部署配置限制批大小、上下文长度和 KV 缓存比例，并通过聊天模板关闭思考模式、适配工具调用，控制单次交互的生成开销。原始模型权重只读挂载，部署参数与模型文件分离，便于复现和切换。Paper Tree 的核心价值，是将 NVIDIA Agent Skills 的研究能力和 DGX Spark 的本地推理能力，落到“从一个具体疑问走向一组相关论文”的可视化阅读过程中。
